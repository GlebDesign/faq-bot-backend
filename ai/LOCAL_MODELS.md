# Настоящие модели на ноутбуке

Подготовлено 19.11.2026 для Intel Core i5-1145G7 (4 ядра / 8 потоков), 16 GB RAM и Intel Iris Xe. Используется CPU. На старте настройки было свободно около 3,8 GB RAM, поэтому сервер загружает одну модель за раз, а после запроса выгружает её из памяти.

По карточкам разработчика обе модели опубликованы с Apache-2.0: [генерация](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), [embeddings](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B). Сведения относятся к выбранным версиям, не ко всем моделям с похожими именами.

Проверенные digest:

- Генерация: `0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`.
- Embeddings: `ac6da0dfba84a81fdbfbaf330198c33cd77c4cdfc53e8bc50eb581914a15621d`.

Runtime — официальный переносной Ollama `0.40.16`. SHA-256 загруженного Windows-архива сверена с официальным `sha256sum.txt`: `50fcf5ad54277f2fa5d173ebfc93bcb017adbc0c9ef2314daabc96ca9e6aa64e`. Для этого ноутбука распакованы CPU-библиотеки, CUDA/Vulkan-библиотеки не устанавливались. Runtime и веса лежат в `ai/.runtime/`; эта папка исключена из Git и Docker-контекста.

## Запуск на этом компьютере

Из папки `ai`:

```powershell
.\start-local.ps1
.\run-local.ps1 doctor
.\run-local.ps1 ingest --account local-demo --agent sales --document delivery .\examples\delivery.md
.\run-local.ps1 ask --account local-demo --agent sales 'Сколько стоит доставка в Москву?'
.\run-local.ps1 ask --account local-demo --agent sales 'Сколько стоит доставка в Казань?'
```

Скрипт `start-local.ps1` запускает Ollama в фоне только на `127.0.0.1:11434`. Если сервер уже отвечает, второй экземпляр не создаётся. Автозапуск Windows и системные переменные окружения не меняются.

`run-local.ps1` выбирает настоящие модели и отдельный индекс `data/local-qwen.sqlite3`. Для собственного индекса передайте `--db` перед командой. Он не подставляет demo-backend. Явно заданные переменные окружения имеют приоритет над профилем скрипта. После команды прежнее окружение PowerShell восстанавливается.

На другом компьютере нужно создать Python-окружение через `setup.ps1`, установить официальный [Ollama для Windows](https://docs.ollama.com/windows) и загрузить выбранные теги. Сам runtime и веса не передаются вместе с репозиторием. Для установленного вне проекта runtime можно передать `start-local.ps1 -OllamaPath 'путь\к\ollama.exe'`.

## Параметры профиля

- 4 CPU-потока, один одновременный запрос, одна загруженная модель.
- Контекст генерации 4096 токенов, ответ ограничен 768 токенами, текст источников — 3000 символами.
- `MODEL_KEEP_ALIVE=0`: веса выгружаются после запроса, поэтому каждый вопрос включает затраты повторной загрузки.
- Thinking выключен; выбранная Instruct-версия рассчитана на обычную генерацию.
- `Temperature=0.7`, `TopP=0.8`, `TopK=20`, `repeat_penalty=1.1`, seed 42. Параметры sampling основаны на [рекомендациях автора](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507#best-practices); seed помогает повторить локальную проверку, но не гарантирует одинаковый текст на любом оборудовании.
- `MIN_SCORE=0.3` — предварительная локальная настройка. На учебном полном документе положительные вопросы давали cosine около 0,37–0,48, вопрос про Плутон — около 0,08. Похожий вопрос без нужного факта проходит к LLM, которая должна вернуть отказ. Это не утверждённый порог для всех клиентских баз.

Внутри запроса источники обозначаются короткими `S1`, `S2` и т. д. В ответе возвращаются настоящие сохранённые chunk IDs. В извлекающем режиме модель получает дословные фрагменты с номерами Q1, Q2 и выбирает citation_ids; пустой список означает отсутствие ответа. JSON-схема ограничивает допустимые номера, код проверяет их и восстанавливает цитату и источник из подготовленной таблицы. Затем RagService дополнительно проверяет соответствие цитаты выбранному источнику. Это не доказывает смысловую правильность любого ответа и не заменяет независимый evaluation.

В локальном профиле включён `QUOTE_ONLY_ANSWERS=true`: LLM решает, есть ли ответ, и выбирает цитату, а итоговый текст берётся дословно из проверенного источника. Это извлекающий режим RAG. Свободный пересказ компактной модели может исказить числа даже при правильной цитате; такой случай встретился при настройке. В обычном `run.ps1` режим определяется настройками, по умолчанию свободный пересказ сохранён.

## Что выяснилось в настоящем прогоне

Первый кандидат `qwen3:1.7b` уверенно отвечал на простые вопросы, но подменял отсутствующий город условиями Москвы. Он не выбран основным. У 4B со старым greedy-профилем возникали повторы внутри цитат; это обнаружила строгая проверка источников. Для рабочего профиля настроены sampling и выбор номеров цитат. На полном файле выявлено также противоречие между has_answer и непустым claims. В извлекающем режиме этот дублирующий флаг не генерируется моделью: он вычисляется из проверенного списка цитат. Проверяющий код продолжает отклонять неподтверждённые ссылки.

Для повторения реальных проверок:

```powershell
.\run-local.ps1 verify
.\run-local.ps1 verify-refusal
```

Первый скрипт проверяет 10 сценариев: известный/неизвестный вопрос, две компании, двух агентов, замену и удаление знаний, а также цену, самовывоз и отсутствующий город из полного examples/delivery.md. Второй принудительно передаёт источник в LLM и проверяет отказ по отсутствующему телефону; порог поиска меняется только внутри этой изолированной проверки. Результаты сохраняются в `.runtime/last-real-smoke.json` и `.runtime/last-real-refusal.json`.

Это небольшой учебный набор, а не доказательство качества на всех документах или нагрузочный тест. Сервисный режим Go/gRPC, RabbitMQ и pgvector добавлен следующим этапом и описан в [AI_INTEGRATION](../docs/AI_INTEGRATION.md).

## Зафиксированный результат — 19.11.2026

- `pytest`: **35 passed**, включая оба формата ответа LangChain и отклонение неизвестных/повторных номеров цитат. `pip check`: несовместимых зависимостей нет.
- `run-local.ps1 verify`: **10/10 passed**, 118,78 секунды на весь прогон с индексацией. Использованы настоящие Ollama и обе модели, без HTTP mocks.
- `run-local.ps1 verify-refusal`: **passed**; LLM получила источник, но отказала по отсутствующему телефону. Наличие usage подтверждает вызов генерации.
- Положительные ответы в финальном прогоне занимали примерно **11–16 секунд** вместе с embeddings и повторной загрузкой весов. Вектор: **1024**. Выбран prompt `faq-extractive-v1`.
- В отдельном замере процесса 4B рабочий набор достигал **3129,7 MiB**, GPU-память не использовалась. Это наблюдение одного запуска, не верхняя граница потребления.
- `doctor`: `ready=true`, оба выбранных тега найдены. Сервер остаётся доступен на localhost; модели выгружаются после каждого запроса.

Машиночитаемые отчёты лежат в исключённой из Git папке `.runtime`. Для повторения на другой машине используйте команды выше; время и результат могут отличаться.

## Сервисный режим после AI-018

Помимо SQLite CLI, модели подключены к отдельным gRPC и AMQP процессам. В них используется PostgreSQL/pgvector, pin по digest, batching и ограниченная DB role. Полный запуск и актуальная граница с Go описаны в [AI_INTEGRATION](../docs/AI_INTEGRATION.md). Ранее перечисленные отсутствующие интеграции относятся к историческому этапу настройки моделей; текущую готовность см. в новом разделе ПРОВЕРКА.md.
