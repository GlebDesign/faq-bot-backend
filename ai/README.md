# FAQ Bot — первый AI-прототип Ростика

Локальный Python CLI на LangChain: загрузка UTF-8 TXT/MD → разбиение текста → embeddings → поиск в знаниях выбранного агента → ответ с проверяемыми ссылками на фрагменты.

Это первый рабочий этап AI-части. Интеграции Go/gRPC, RabbitMQ, pgvector, PDF/DOCX, история диалога и Coverage ещё не реализованы. Поиск прототипа хранится в SQLite и выполняется линейно; для небольшого учебного набора этого достаточно. Модуль добавлен в подпапку ai репозитория backend; исходные проектные документы не менялись.

## Запустить прямо сейчас

Окружение устанавливается отдельно для этой копии. Для первого запуска выполни `setup.ps1`, затем запускай demo. Открой PowerShell в папке `ai`:

```powershell
.\setup.ps1
.\run.ps1 demo
```

Команда проверяет шесть сценариев: ответ с источником, отсутствие ответа, изоляция компаний, изоляция агентов, замена и удаление документа. При успехе выводит JSON с `passed: true` и завершается с кодом 0.

**Демо работает без LLM:** использует хеши слов вместо семантических embeddings и детерминированное извлечение строки вместо генерации. Оно проходит через настоящий код индексации, поиска, LangChain-промпт и проверку источников. Это проверка логики, а не измерение качества AI. Данные демо временные и не сохраняются в рабочем индексе.

## Подключить настоящие модели

Нужен работающий Ollama с двумя выбранными командой моделями: генеративной и embedding-моделью. Генеративная модель должна поддерживать структурированный JSON-ответ. Приложение не скачивает веса и не выбирает модели за команду.

Задай реальные точные теги в текущем PowerShell:

```powershell
$env:OLLAMA_BASE_URL = 'http://127.0.0.1:11434'
$env:LLM_MODEL = 'ЗАМЕНИ_НА_ТЕГ_МОДЕЛИ_ГЕНЕРАЦИИ'
$env:EMBEDDING_MODEL = 'ЗАМЕНИ_НА_ТЕГ_EMBEDDING_МОДЕЛИ'
.\run.ps1 doctor
```

`doctor` проверяет доступность runtime и наличие тегов, но не запускает inference и не подтверждает качество/производительность модели. Если runtime или модели не готовы, код завершения 1. На момент подготовки проекта Ollama на `127.0.0.1:11434` не отвечал.

Загрузить учебный файл и задать вопрос:

```powershell
.\run.ps1 ingest --account company-a --agent sales --document delivery .\examples\delivery.md
.\run.ps1 ask --account company-a --agent sales 'Сколько стоит доставка в Москву?'
.\run.ps1 ask --account company-a --agent sales 'Кто открыл Плутон?'
.\run.ps1 status --account company-a --agent sales
```

Другой агент с противоречащими фактами:

```powershell
.\run.ps1 ingest --account company-a --agent other --document delivery .\examples\other-agent.md
.\run.ps1 ask --account company-a --agent other 'Сколько стоит доставка в Москву?'
```

Удалить документ:

```powershell
.\run.ps1 delete --account company-a --agent sales --document delivery
```

Чтобы заменить документ, отредактируй файл и повтори `ingest` с теми же account/agent/document. Предыдущие фрагменты удаляются в одной транзакции с сохранением новых. Сбой embeddings до сохранения оставляет старую версию доступной.

Рабочий индекс по умолчанию — `data/knowledge.sqlite3`. Другой путь задаётся **перед** названием команды:

```powershell
.\run.ps1 --db .\data\another.sqlite3 status --account company-a --agent sales
```

Для токенов без данных возвращаются `null` и `usage_available: false`. Сбой runtime возвращает JSON `error` и код завершения 2; он не маскируется под обычное «ответа нет».

## Настройки

`.env.example` — справочник переменных, файл автоматически не загружается. Переменные нужно установить в PowerShell или в окружении процесса. Локальная трассировка не отправляет документы в LangSmith: CLI отклоняет запуск с включёнными `LANGSMITH_TRACING`, `LANGCHAIN_TRACING_V2` или `LANGCHAIN_TRACING`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `LLM_MODEL` / `EMBEDDING_MODEL` | Пусто | Реальные теги моделей, обязательны для ingest/ask |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Доверенный адрес runtime, без credentials в URL |
| `EMBEDDING_REVISION` | `1` | Версия весов/настроек embedding-модели |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `800` / `120` | Размер фрагмента и перекрытие в символах |
| `TOP_K` | `4` | Максимум фрагментов в контексте |
| `MIN_SCORE` | `0.5` | Пример порога cosine similarity, требует калибровки |
| `CONTEXT_CHARS` | `6000` | Бюджет текста источников в символах |
| `OLLAMA_TIMEOUT` | `60` | Таймаут сетевых операций, секунды |

После смены embedding-модели или её весов/настроек увеличь `EMBEDDING_REVISION` и переиндексируй все документы агента. Разные embedding-конфигурации не смешиваются, несовпадение размерностей вызывает `stale_index`. Изменение весов под прежним тегом автоматически не обнаруживается: используйте зафиксированные теги и учёт версий. Размеры фрагментов и модельный контекст нужно подобрать на реальном железе; лимит символов не является точным подсчётом токенов.

## Как устроен код

- `src/faq_ai/config.py` — переменные окружения и ограничения.
- `src/faq_ai/rag.py` — загрузка, разбиение, поиск, промпт и проверка цитат.
- `src/faq_ai/backends.py` — настоящие `ChatOllama`/`OllamaEmbeddings` и явно отдельные demo-замены.
- `src/faq_ai/store.py` — SQLite, scope, замена/удаление и версии знаний.
- `src/faq_ai/models.py` — схемы данных и ошибок.
- `src/faq_ai/cli.py` — команды запуска; `demo.py` — автономная демонстрация.
- `tests/` — проверки изоляции, версий, ошибок и реальных LangChain-адаптеров с HTTP-фикстурами.

Используются [ChatOllama](https://docs.langchain.com/oss/python/integrations/chat/ollama), [OllamaEmbeddings](https://docs.langchain.com/oss/python/integrations/embeddings/ollama) и [RecursiveCharacterTextSplitter](https://docs.langchain.com/oss/python/integrations/splitters/recursive_text_splitter). Точные установленные зависимости зафиксированы в `requirements.lock.txt`.

## Воспроизвести окружение на другом компьютере

Нужен настоящий установленный Python 3.11+, проверено на Python 3.12. Скрипт `setup.ps1` создаёт окружение и устанавливает закреплённые зависимости. Он использует установленный Python или доступный встроенный runtime Codex. Можно явно указать путь: `.\setup.ps1 -Python 'C:\Python312\python.exe'`. Для ручной установки:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\run.ps1 demo
.\.venv\Scripts\python.exe -m pytest -q
```

Папка `.venv` не переносится между компьютерами и не добавляется в Git. Веса моделей устанавливаются отдельно у Сергея/на выбранном узле.

## Ограничения первого этапа

- Это локальный инструмент доверенного разработчика. Account/agent в CLI задаются вручную: SQL-фильтр проверен, серверной авторизации нет. Перед публичным использованием scope должен приходить только из доверенного Go-контракта.
- Источники ограничены найденными фрагментами. Неизвестные ID и выдуманные цитаты отклоняются. Проверка существования цитаты **не доказывает**, что сгенерированная формулировка логически следует из неё; нужен независимый набор и оценка на настоящей модели.
- Промпт отделяет инструкции от документов, tools не подключены. Тест с вредным документом проверяет границы данных, а не неуязвимость любой LLM к prompt injection.
- Порог поиска и политика отказа пока не калиброваны. Ответы, задержки, устойчивость к противоречиям и перефразировкам нельзя оценить по детерминированному demo.
- Замена/удаление атомарны в локальном хранилище; изменение версии во время генерации приводит к `knowledge_changed`. Распределённые гарантии, tombstone/fencing для очередей и нагрузки production не реализованы.
- Файлы ограничены 2 MB и 1000 фрагментами на документ, вопросы — 2000 символами. Индекс и полные тексты документов хранятся локально без шифрования; использовать разрешённые учебные данные.

Следующий этап после проверки моделей: общий с Даней `.proto`, перенос поиска в pgvector, worker RabbitMQ, затем парсеры PDF/DOCX и история диалога. Этот прототип не закрывает целиком §13 спецификации.
