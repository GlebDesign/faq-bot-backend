# HTTP-сервер

Go API использует стандартный `net/http.ServeMux`. Точка входа —
`backend/cmd/api/main.go`, маршруты — `backend/internal/handlers/router.go`.
Запуск, Docker и переменные описаны в [BACKEND.md](BACKEND.md).

## Маршруты

| Путь | Метод | Назначение |
| --- | --- | --- |
| `/health/live` | GET, HEAD | Процесс работает, БД не проверяется |
| `/health/startup` | GET, HEAD | Начальная настройка завершена |
| `/health/ready` | GET, HEAD | Сервер готов; при настроенной БД проверяется соединение |
| `/api/v1/auth/csrf`, `/api/v1/auth/session` | GET | CSRF-токен и данные текущей сессии |
| `/api/v1/auth/register`, `/api/v1/auth/login`, `/api/v1/auth/logout` | POST | Регистрация, вход, выход |

Маршруты Auth подключаются только при полной конфигурации. Неизвестные пути
возвращают 404. Примеры Auth — в [AUTH.md](AUTH.md).

Проверка из любого каталога при работающем API:

```sh
curl -i http://127.0.0.1:8080/health/live
curl -I http://127.0.0.1:8080/health/startup
curl -i http://127.0.0.1:8080/health/ready
```

После старта ожидается 200, GET возвращает `{"status":"ok"}`, HEAD — без тела.
До готовности startup/ready возвращают 503. При остановке снимается ready,
live/startup остаются успешными до закрытия порта сервера. Проверка соединения с БД ограничена 1 секундой.
Недоступная БД даёт ready=503, но live=200. Существование таблиц и доступность
Supabase не проверяются этими маршрутами.

## Ответы и ограничения

Ошибки возвращаются JSON-объектом с полями `code`, `message`, `request_id`.
Неизвестный путь даёт 404; неверный метод проверки состояния — 405 с `Allow: GET, HEAD`.
Ответы получают `Cache-Control: no-store` и `X-Request-ID` — идентификатор для
сопоставления запросов, не доказательство прав пользователя. Входное значение X-Request-ID
принимается как `[A-Za-z0-9_-]{1,80}`, иначе создаётся случайное.

Серверные таймауты: заголовки 5s, чтение 15s, запись 30s, idle 60s;
максимум заголовков 1 MiB. Ограничения JSON и частоты запросов Auth — в [AUTH.md](AUTH.md).
Логи JSON содержат запуск, остановку и безопасные ошибки; секреты и тела запросов
в них не выводятся.

## Остановка

SIGINT/SIGTERM снимает готовность принимать запросы и вызывает `Server.Shutdown`. На завершение
текущих запросов выделяется `HTTP_SHUTDOWN_TIMEOUT`, затем соединения закрываются
принудительно с ошибкой. Задержки для распространения readiness в оркестраторе нет.

Для ручной проверки из `backend`:

```sh
go build -o /tmp/faq-api ./cmd/api
/tmp/faq-api
```

В другом терминале послать `kill -TERM <PID>` именно собранному процессу.
`go run` использует дополнительный процесс-обёртку. Автотест в `cmd/api/main_test.go`
запускает отдельный процесс и проверяет его остановку. Для теста нужно разрешение
открывать локальный TCP-порт.
